# Decision-Making Framework

## For Any Major Decision

Apply this framework before committing time or money:

### The Five Questions

| # | Question | Weight | Score (1-5) |
|---|----------|--------|-------------|
| 1 | Does this move us closer to our next MRR milestone? | High | |
| 2 | Does it improve retention or reduce churn? | High | |
| 3 | Can we measure its impact within 30 days? | Medium | |
| 4 | What is the cost in time and money vs. expected return? | Medium | |
| 5 | What is the risk if it fails? | Medium | |

**Scoring:**
- 5 = Strong yes / very positive
- 4 = Yes / positive
- 3 = Neutral / uncertain
- 2 = No / negative
- 1 = Strong no / very negative

### Decision Rules

| Total Score | Action |
|-------------|--------|
| 20-25 | **Proceed immediately.** High confidence, high alignment. |
| 15-19 | **Proceed with caution.** Set a 30-day review checkpoint. |
| 10-14 | **Delay.** Gather more data or reduce scope. Revisit next month. |
| 5-9 | **Reject.** Does not align with priorities or risk is too high. |

### Quick Decisions (< $500 or < 1 day)

For small decisions, use the 2-minute rule:
- Can I reverse this decision easily? → Just do it.
- Will this matter in 6 months? → If no, just do it.
- Is this blocking something more important? → If yes, just do it.

### Common Decision Traps

**Sunk Cost Fallacy**
- "We've already spent X on this, we can't stop now."
- **Fix:** Ask "If we were starting fresh today, would we still choose this?"

**Shiny Object Syndrome**
- "This new tool/feature looks amazing, let's try it."
- **Fix:** Run through the 5 questions. If it doesn't score 15+, pass.

**Analysis Paralysis**
- "We need more data before deciding."
- **Fix:** Set a decision deadline. 80% confidence is enough.

**Founder Ego**
- "I know this will work because I built it."
- **Fix:** What would the data say? What would a neutral observer say?

### Emergency Decisions (P0)

When something is on fire:
1. **Assess impact** — how many customers affected? For how long?
2. **Contain** — stop the bleeding first
3. **Communicate** — notify affected users within 30 minutes
4. **Fix** — implement the fastest viable fix
5. **Retro** — document what happened within 24 hours

**Emergency authority:** The person closest to the problem decides. No waiting for approval.
